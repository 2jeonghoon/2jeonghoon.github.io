## 오늘의 질문

클라이언트와 서버 사이에서 데이터를 중계하는 TCP 프록시를 개발합니다. 클라이언트가 요청을 모두 보낸 뒤 송신 방향만 종료했지만 서버 응답은 아직 도착하지 않았습니다. 프록시는 두 소켓을 즉시 모두 닫아도 될까요? 각 방향의 EOF와 미전송 데이터를 어떻게 관리하겠습니까?

## 핵심 해설

송신 종료와 전체 연결 종료를 구분해야 한다. 클라이언트가 shutdown(SHUT_WR)을 하면 더 보내지 않지만 서버 응답을 받을 수 있다. 프록시는 두 TCP 연결의 종단이며 양쪽 수신 EOF와 자신이 보유한 송신 대기 데이터를 직접 관리한다.

~~~text
클라이언트 → [서버행 큐] → 서버
클라이언트 ← [클라이언트행 큐] ← 서버
~~~

클라이언트 측 recv가 0이 되면 클라이언트에서 더 읽지 않되 이미 수신한 서버행 큐를 계속 보낸다. 큐를 모두 send한 뒤 서버 측 소켓에 shutdown(SHUT_WR)하여 종료를 요청 데이터 뒤에 전달한다. 이는 커널 송신 큐의 데이터 처리와 FIN 순서를 이용하며 상대 애플리케이션의 처리 완료를 뜻하지는 않는다.

서버 응답은 계속 수신하여 클라이언트행 큐에서 전달한다. 서버 EOF를 받으면 그 큐도 배출한 뒤 클라이언트 소켓의 송신 방향을 종료한다. 양방향 처리가 끝나고 사용자 공간 대기 데이터가 없으면 최종 close한다. 영구 오류와 종료 타임아웃 정책은 별도다.

미전송 데이터는 프록시가 아직 send하지 못한 바이트다. 이전 send의 양수 반환만큼 오프셋을 이동하고 남은 부분만 보낸다. TCP 손실 패킷 재전송은 각 연결의 TCP 스택이 처리한다. 이미 보낸 메시지 전체를 프록시가 임의 재전송하면 중복 처리가 생길 수 있다.

## 면접용 모범 답변

클라이언트의 송신 종료는 응답 수신까지 끝났다는 뜻이 아니므로 즉시 모두 닫지 않겠습니다. 각 방향의 EOF와 송신 큐를 별도로 관리하고 클라이언트 EOF 후 서버행 큐를 배출한 뒤 서버 측에 SHUT_WR을 적용하겠습니다. 응답 방향도 같은 방식으로 처리한 후 두 연결을 정리하겠습니다.
