## 1.1 왜 새로운 비교 연산자가 필요한가

값 타입에 관계 연산자를 각각 구현하면 같은 기준을 여러 번 적는다.
그중 하나가 다른 멤버를 비교하면 정렬과 동등성의 관계가 깨진다.
C++20은 비교 결과를 하나의 범주 값으로 표현하고 관계 연산에 활용한다.

`<=>`는 왼쪽이 작은지, 같은 순서인지, 큰지, 또는 비교 불가능한지를 표현한다.
다만 사용자 정의 `<=>`를 작성했다고 `==`까지 자동으로 생기는 것은 아니다.
자동 동등 비교 선언은 뒤에서 설명할 **기본 정의된 `<=>`**의 특별한 규칙이다.

## 1.2 비교를 정의하고 사용하기

아래는 독립 실행 예제다.

```cpp
#include <compare>
#include <cassert>

struct Revision {
    int major;
    int minor;
    auto operator<=>(const Revision&) const = default;
};

int main() {
    Revision stable{2, 4};
    Revision preview{3, 0};
    assert(stable < preview);
    assert((stable <=> preview) < 0);
    assert(stable != preview);
}
```

기본 비교는 선언된 멤버 순서대로 사전식 비교를 한다.
따라서 위 타입은 `major`를 먼저 보고, 같을 때만 `minor`를 본다.
데이터 멤버의 선언 순서를 바꾸는 일이 외부 정렬 규칙까지 바꿀 수 있다.

비교 범주는 단순히 음수 정수 세 종류가 아니다.

| 범주 | 판단할 내용 | 예시 |
| --- | --- | --- |
| `strong_ordering` | 순서상 같음이 대체 가능성을 뜻하는가 | 정수 기반 버전 |
| `weak_ordering` | 다른 표현을 같은 순서로 취급하는가 | 대소문자를 무시하는 이름 |
| `partial_ordering` | 서로 순서를 정하지 못하는 값이 있는가 | NaN이 포함된 부동소수점 |

결과는 `0`과 비교한다. 임의의 정수 코드와 비교하는 인터페이스가 아니다.
부분 순서에서 `!(a < b) && !(a > b)`가 곧 동등함을 뜻하지 않는다.
비교 불가능한 경우까지 포함되기 때문이다.

여러 정렬 기준을 직접 결합한다면 앞선 비교가 0이 아닐 때 바로 반환한다.
반환 범주가 서로 다르면 공통 범주를 명시하거나 설계를 다시 확인한다.
예를 들어 정수와 실수 멤버가 함께 있으면 전체 비교는 부분 순서가 될 수 있다.

## 1.3 기본 정의된 동등 비교와 삼방향 비교

`= default`는 모든 직접 기반 클래스와 비정적 데이터 멤버를 대상으로 한다.
일부 필드가 캐시이거나 통계라면 기본 비교가 도메인 의미와 맞지 않을 수 있다.
그때는 식별에 필요한 필드만 비교하는 함수를 직접 작성한다.

직접 작성한 `<=>`와 `==`는 서로 일관되어야 한다.
길이가 다르면 곧바로 다르다고 판단할 수 있는 시퀀스에서는 `==`의 구현이 더 저렴할 수 있다.
따라서 모든 동등 비교를 삼방향 비교 호출로 대체하는 것은 좋은 기본값이 아니다.

멤버에 필요한 비교가 없으면 기본 정의한 연산자가 삭제될 수 있다.
`auto` 반환형이라고 기존 `<`와 `==`만 있는 멤버의 모든 비교를 자동 합성하는 것도 아니다.
명시적인 비교 범주를 쓰는 경우의 합성 규칙과 구분해서 읽는다.

## 1.4 재작성된 표현식과 오버로드 결정

컴파일러는 관계 연산자를 찾을 때 `<=>`에서 파생되는 재작성 후보를 고려한다.
동등 연산에서도 `==`를 이용한 `!=`와 역순 후보가 관여한다.
이는 소스에 연산자 함수 여섯 개를 실제로 추가한다는 뜻이 아니다.

암시적 변환이 많은 타입이나 기존의 비대칭 비교 함수는 후보 관계가 달라질 수 있다.
마이그레이션할 때는 `a == b`뿐 아니라 `b == a`도 점검한다.
함수 호출 구문으로 `operator<(a, b)`를 쓰는 경우와 연산자 표현식도 구분한다.

## 1.5 제네릭 코드에서 비교하기

`std::compare_three_way`는 비교 함수를 객체로 전달할 때 유용하다.
`std::lexicographical_compare_three_way`는 두 구간을 원소 순서대로 비교한다.
첫 원소 차이가 결정적이고, 공통 접두부가 같으면 길이가 짧은 쪽이 앞선다.

제네릭 코드에서는 요구하는 순서 수준을 먼저 정한다.
정렬 알고리즘이 필요로 하는 엄격 약순서를 부분 순서가 저절로 보장하지 않는다.
NaN을 받을 수 있다면 제외할지, 별도 위치로 정렬할지 정책이 필요하다.

## 1.6 기존 비교 코드와의 호환성

기존 자유 함수가 다른 연산자에 위임하던 구조는 재작성 규칙과 함께 검토한다.
무심코 대칭 위임을 추가하면 재귀 호출이나 모호성이 생길 수 있다.
상속에서는 기반 부분의 비교가 파생 타입의 의미에 맞는지도 확인한다.
보호 멤버 접근은 함수가 선언된 위치와 접근 문맥의 영향을 받는다.
