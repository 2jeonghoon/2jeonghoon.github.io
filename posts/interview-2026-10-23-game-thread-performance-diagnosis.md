## 오늘의 질문

Unreal 기반 게임에서 플레이어가 밀집하면 프레임이 끊긴다. 같은 장면을 측정한 결과는 다음과 같다. 각 시간은 겹쳐 실행될 수 있으므로 단순히 합산하지 않는다.

| 항목 | 평상시 | 끊김 발생 시 |
| --- | ---: | ---: |
| 전체 프레임 | 16.7ms | 42ms |
| Game Thread | 7ms | 40ms |
| Render Thread | 5ms | 8ms |
| GPU | 10ms | 11ms |

개발자는 “화면에 캐릭터가 많으니 해상도를 낮추고, 모든 캐릭터에 오브젝트 풀링을 적용하자”고 제안한다.

1. 가장 먼저 의심할 병목은 무엇인가? 알 수 있는 사실과 아직 모르는 원인을 구분하라.
2. 다음 측정에서 확인할 작업 후보 두 가지와 원인을 좁힐 비교 실험 하나를 제안하라.
3. 해상도 감소와 오브젝트 풀링은 각각 어떤 측정 결과가 나왔을 때 타당한가?

## 핵심 해설

### 1. Game Thread를 우선 조사하되 연산량 증가로 단정하지 않는다

Game Thread 시간이 7ms에서 40ms로 증가했으므로 우선 조사 대상이다. GPU 시간은 10ms에서 11ms로 변화가 작다. 이 자료만으로 해상도 감소를 첫 해결책으로 선택할 근거는 부족하다.

하지만 Game Thread의 긴 시간이 특정 함수의 연산 증가를 의미한다고 확정할 수는 없다. 실제 작업 실행 시간과 다른 작업 완료를 기다린 시간을 구분해야 한다. 정확한 측정 범위와 스레드 간 의존 관계도 타임라인에서 확인한다.

### 2. 후보를 세우고 한 조건씩 바꿔 비교한다

| 후보 | 확인할 내용 |
| --- | --- |
| 캐릭터 Tick·이동·충돌 처리 | 밀집 시 실행 횟수나 작업 한 번당 비용이 늘어나는지 |
| 객체 생성·파괴·GC | 주변 이펙트나 임시 객체의 생성·정리가 끊김과 겹치는지 |

프로파일러에서는 끊김 프레임을 선택하고 후보 작업의 소요 시간과 실행 횟수를 확인한다. 함수의 전체 시간에는 하위 호출이 포함될 수 있으므로 부모와 자식 시간을 중복 합산하지 않는다. 자체 시간과 하위 호출을 포함한 시간을 함께 보면 비용의 위치를 좁히기 쉽다.

비교 실험으로 캐릭터 수와 카메라를 유지한 테스트 환경에서 캐릭터 간 충돌만 비활성화해 본다. 같은 구간을 반복 측정해 Game Thread 시간과 끊김이 줄어들면 충돌 처리 경로를 더 자세히 조사할 근거가 된다.

다만 충돌을 끄면 실제 캐릭터 배치나 동작도 달라질 수 있다. 가능한 한 조건을 일정하게 유지하고 충돌 검사 횟수와 관련 작업 시간도 함께 확인한다. 한 번의 결과만으로 원인을 확정하지 않는다.

### 3. 해결책마다 줄일 수 있는 비용이 다르다

해상도 감소는 픽셀 처리량에 민감한 GPU 병목에서 효과를 기대할 수 있다. 같은 장면에서 해상도를 낮췄을 때 GPU 시간과 전체 프레임 시간이 얼마나 줄어드는지 확인한다. 모든 GPU 병목이 해상도에 같은 비율로 반응하는 것은 아니다.

오브젝트 풀링은 반복적인 생성·파괴와 초기화·정리 비용이 주요 원인일 때 검토한다. 생성·파괴 이벤트와 끊김이 겹치는지 확인하고, 재사용을 적용한 실험에서 비용이 줄어드는지 검증한다.

풀링은 유지 중인 객체의 Tick이나 충돌 비용을 자동으로 줄이지 않는다. 재사용 시 상태 초기화와 비활성 객체의 Tick·충돌·네트워크 처리 정책도 필요하다. 따라서 모든 캐릭터에 일괄 적용하기 전에 실제 비용을 확인해야 한다.

## Unreal에서 확인하는 방법

Unreal Insights의 Timing Insights는 CPU와 GPU 활동을 타임라인으로 분석하는 도구다. 끊김 구간의 Game Thread와 관련 작업을 확대해 실행 경로를 확인한다. 작업 대기가 의심되면 관련 태스크와 다른 스레드의 진행도 함께 살핀다. 프로젝트 고유 함수가 충분히 구분되지 않으면 필요한 구간에 추적 범위를 추가한다.
