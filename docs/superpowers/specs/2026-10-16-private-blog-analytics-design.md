# 비공개 조회 통계와 소유자 전용 관리

작성일: 2026-10-16
상태: 구현 전 사용자 검토용

## 목적과 기존 구조

방문자의 홈·글 조회 수를 기록하고 GitHub 소유자 계정인 `2jeonghoon`만
통계와 글 관리 기능을 이용한다. 공개 블로그에는 관리 버튼을 표시하지 않는다.
사용자는 조회 수를 비공개로 운영하는 방향으로 진행을 요청했다.

공개 사이트는 GitHub Pages이며 관리자 서비스는 별도 Cloudflare Worker다.
관리 API는 이미 GitHub numeric ID `51705815`와 서명된 HttpOnly 세션을 검사한다.
현재 공개 `index.html`의 Write와 `blog.js`의 Manage post는 인증 없이 표시된다.
Worker의 정적 관리자 HTML은 로그인 전에도 전달되지만 workspace는 숨겨져 있다.

## 접근 방식과 선택

1. 기존 Worker + D1: 기존 인증을 재사용하면서 날짜별·글별 집계를 직접 관리한다.
   저장소 바인딩과 마이그레이션 운영이 추가되지만 이번 요구에 가장 잘 맞는다.
2. 외부 분석 서비스: 집계 기능은 빨리 확보할 수 있으나 별도 계정·대시보드와
   관리자 UI 연동이 필요하다.
3. 브라우저 저장소만 사용: 다른 방문자의 기록을 합산할 수 없어 목적에 맞지 않는다.

1번을 선택한다. 공개 사이트와 관리자의 도메인을 변경하지 않는다.

## 관리 화면과 로그인

- 공개 헤더의 Write와 글 상세의 Manage post를 제거한다. 페이지 로딩 중에도
  관리 링크가 나타나지 않는다. 공개 사이트에서 소유자 쿠키를 조회하지 않는다.
- 소유자는 기존 `https://jh-log-admin.2jeonghoon.workers.dev/`를 북마크하여
  GitHub로 로그인한다. 로그인 후 글쓰기·수정·카테고리·통계 화면을 이용한다.
- 공개 `/admin/` 경로는 기존 관리자 로그인 주소로 안내하는 기능만 유지한다.
  이 주소 자체는 비밀이 아니며 주소를 알아도 인증을 우회할 수 없다.
- 비로그인 요청에는 로그인 안내만 제공하고 실제 workspace HTML과 관리자
  데이터는 인증 후에만 반환하도록 Worker의 HTML 라우팅을 보호한다.
- HTML 라우팅은 `/`와 `/index.html`을 모두 검사하고 사용자별 HTML은
  `Cache-Control: no-store`로 응답한다. Worker 우선 라우팅 설정도 함께 변경한다.
- 관리자 정적 JS/CSS 소스의 비밀 유지는 목표가 아니다. 모든 API의 서버 인증이
  실제 접근 경계다. 기존 Origin·CSRF·본문 검증을 유지한다.

이는 공개 블로그에서도 소유자에게만 버튼을 다시 표시하는 구현과는 차이가 있다.
별도 도메인의 쿠키를 약화하거나 브라우저에 관리 토큰을 저장하지 않기 위해
관리 작업은 관리자 주소에 모은다.

## 조회 수 정의와 수집

- 조회 대상은 홈(`/`)과 실제로 렌더링된 공개 글의 slug다. 404는 집계하지 않는다.
- 페이지를 한 번 표시하면 해당 대상에 대해 수집 요청을 한 번 전송한다.
- sessionStorage에 페이지별 마지막 전송 시각을 저장하여 같은 탭에서 같은
  페이지를 30분 안에 새로고침하면 다시 전송하지 않는다. 저장소 접근 실패 시
  집계를 포기하고 본문 사용에는 영향을 주지 않는다.
- 성공 응답 후에 전송 시각을 기록한다. 요청 중에는 메모리 플래그로 중복을 막는다.
- 수집은 best effort다. 광고 차단, 네트워크 장애, 다른 탭·기기 등으로 실제 열람과
  차이가 있으므로 정확한 방문자 수라고 표시하지 않는다.
- 방문자 식별자, IP, User-Agent, referrer, 전체 URL, 쿼리 문자열을 통계 DB에
  저장하지 않는다. 날짜와 페이지별 누적 숫자만 저장한다.
- 일자는 서버 시각을 Asia/Seoul 기준 `YYYY-MM-DD`로 변환한다.
- 과거 기록은 복원하지 않는다. 배포 후 최초 수집부터 누적한다.

## 데이터와 API

D1 바인딩 이름은 `ANALYTICS_DB`로 한다. 마이그레이션에서
`daily_views(day TEXT, page TEXT, views INTEGER, PRIMARY KEY(day,page))`를 생성한다.
동시 수집 시 유실되지 않도록 바인딩된 SQL의 단일 UPSERT로 숫자를 증가시킨다.
day와 page 외의 방문 원본은 저장하지 않는다. 집계 데이터는 삭제하지 않고 누적한다.

### 공개 쓰기 전용 수집

`POST /api/analytics/view`는 `{page: "/"}` 또는 `{page: "<slug>"}`를 받는다.
공개 블로그의 정확한 Origin만 허용하고, JSON과 작은 본문 크기를 강제한다.
slug는 기존 slug 규칙과 배포 시 생성한 공개 글 목록으로 검증한다.
초안이나 존재하지 않는 글은 거부한다. 배포 빌드가 공개 slug 목록을 Worker용으로
생성하도록 하고, Worker 배포 전에 이를 갱신하는 스크립트를 제공한다.
알려진 공개 slug의 삭제·추가는 Worker 재배포 때 반영됨을 운영 문서에 명시한다.

OPTIONS와 수집 응답에만 허용된 공개 Origin의 CORS를 설정한다.
쿠키와 `Access-Control-Allow-Credentials`는 사용하지 않는다.
이 경로는 관리자 세션을 요구하지 않지만 공개 읽기 API는 만들지 않는다.
기존 API와 별도의 Cloudflare rate limiter를 적용한다. Origin 검사는 브라우저
오용을 줄이는 장치이며 임의 HTTP 클라이언트의 조작을 완전히 방지하지 않는다.
수집 경로는 기존 auditRequest에서 제외하여 통계 수집으로 IP 해시 로그가
새롭게 쌓이지 않도록 한다. 오류에는 요청 ID와 일반 오류만 반환한다.

### 소유자 통계 조회

`GET /api/analytics`는 기존 소유자 세션과 읽기 요청 제한을 적용하고
GitHub Contents API 호출 전에 처리한다. 전체 누적, 한국 시간 오늘 조회 수,
최근 30일 날짜별 조회 수, 전체 누적 페이지별 조회 수를 반환한다.
날짜별 표는 조회가 없는 날짜도 0으로 표시한다. 페이지별 목록은 조회 수 내림차순,
동률은 페이지 이름 순으로 정렬한다. 삭제된 글의 과거 집계도 slug로 유지한다.
서버가 날짜 범위를 고정하므로 무제한 사용자 SQL/날짜 범위는 허용하지 않는다.
관리자 화면에서 합계 카드와 날짜별·페이지별 표로 제공하며 공개 화면에는
조회 수를 출력하지 않는다. 데이터는 textContent로 렌더링한다.

## 장애와 배포

DB가 미연결되거나 조회가 실패하면 통계 화면에 사용 불가 메시지를 표시한다.
이를 0건으로 위장하지 않고 기존 글쓰기·수정 기능은 계속 작동한다.
수집 실패도 공개 본문 렌더링을 막지 않는다.

구현에 SQL 마이그레이션, Wrangler D1 바인딩 설정, 공개 slug 생성과 Worker
배포 순서, DB 생성·마이그레이션·배포·롤백 안내를 포함한다.
실제 DB ID는 Cloudflare에서 생성한 값을 사용하고 가짜 ID를 배포하지 않는다.
계정 접근이 가능하면 생성과 배포를 수행하며 불가능하면 필요한 설정만 명시한다.
기존 글 데이터·GitHub App 비밀값·소유자 ID를 변경하지 않는다.

## 검증과 완료 조건

- 비로그인·다른 계정·위조 및 만료 세션은 관리자 API와 통계 조회를 할 수 없다.
- 로그인 전에는 관리자 workspace가 HTML 응답에 포함되지 않고, 소유자는
  기존 글쓰기·카테고리 관리와 새 통계를 이용할 수 있다.
- 공개 홈과 글, 빌드 결과에 Write 및 Manage post 링크가 없다.
- 정상 수집, 잘못된 Origin/본문/slug/메서드, CORS preflight, rate limit,
  D1 실패와 바인딩 누락을 테스트한다.
- 실제 SQLite/D1 호환 환경에서 UPSERT와 전체·오늘·30일·페이지별 집계를 검증한다.
- 한국 시간 자정 경계와 sessionStorage 중복 방지·실패 시 본문 유지도 검증한다.
- 기존 `npm run validate:blog` 및 Worker 관련 테스트가 통과해야 한다.
- 배포했다면 공개 사이트와 Worker에서 인증 없는 통계 조회 차단, 수집 성공,
  관리 링크 제거를 확인한다. 소유자 로그인 UI 확인에 직접 로그인이 필요하면
  이를 미검증 항목으로 명확히 보고한다.
